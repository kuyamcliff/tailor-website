# 3D assets

The fitting studio loads one **body** model and one **garment** model per garment type, both as
glTF binary (`.glb`). Options switch named parts on and off; measurements and some options drive
shape keys (morph targets). This document is the contract a 3D artist needs to deliver models that
drop into the studio without code changes.

## Current state

The published models are **development stand-ins** generated by
`frontend/scripts/build-standin-assets.mjs`. They are clean and correctly wired, but they are
simplified shapes, not tailoring. They are registered with `productionQuality: false`; the studio
tells customers it is a simplified preview, and Owner > 3D assets warns until they are replaced.
Do not market the studio as an accurate fitting tool until production models are published.

## File requirements

- glTF 2.0 binary, Y up, metres, figure facing +Z, feet on y = 0.
- Two levels of detail per asset: `high` (desktop, under 4 MB) and `low` (phones, under 1.5 MB).
- Extensions are checked on upload against an allow-list (material extensions such as sheen and
  clearcoat, texture transform, mesh quantization, Draco, meshopt, Basis textures). Unknown
  extensions are rejected. The studio currently loads models without Draco, meshopt or Basis
  decoders, so do not use those compressions until the decoders are added to
  `frontend/features/studio/viewer.tsx` and served from this site.
- UVs on fabric parts in **metres** (1 UV unit = 1 m of cloth), so a texture's `repeat` value in the
  fabric settings means tiles per metre on every garment.
- Materials: name the main cloth material `fabric`. The studio replaces it with the chosen fabric
  (colour, normal and roughness maps, sheen). Keep buttons, linings and shirts as their own
  materials (`button`, `lining`, `shirt`).
- No embedded textures for cloth; fabrics come from Owner > Fabrics.

## Shape keys

Every mesh in a body and in its garments must have these shape keys, with the same meaning, so the
garment follows the body:

| Shape key   | Influence 1.0 means |
|-------------|---------------------|
| `chest`     | +10 cm chest (bust on the feminine body) circumference |
| `waist`     | +10 cm waist circumference |
| `hip`       | +10 cm seat circumference |
| `shoulders` | +5 cm shoulder width |

Negative influences are used for smaller measurements, so the deltas must be symmetrical enough to
look right at -1.5. Record the model's own measurements in the asset's `bodyCompat.baseMm`
(`height`, `chest`, `waist`, `hip`, `shoulder` in millimetres); the studio computes influences as
`(customer measurement - base) / step`. Height scales the whole figure.

Garment-specific shape keys, driven by options:

| Garment | Shape key | Driven by |
|---|---|---|
| Trousers, suits | `leg_wide` | Leg shape: tapered 0, straight 0.5, wide 1 |
| Jackets, suits | `lapel_width` | Lapel width option (cm), relative to the default |
| Dresses, gowns | `length_midi`, `length_floor` | Length option |

## Part names

Options show and hide nodes by name (configured per option value in Owner > Garments). The
stand-ins use these names; production models should keep them so no option needs reconfiguring.

- **Suit / jacket / trousers** (one model, jacket-only and trousers-only hide the other half):
  `jacket_body`, `jacket_collar`, `sleeve_left`, `sleeve_right`, `lapel_notch`, `lapel_peak`,
  `lapel_shawl`, `buttons_1`, `buttons_2`, `buttons_3`, `buttons_db`, `pocket_flap`,
  `pocket_jetted`, `pocket_patch`, `chest_pocket`, `trousers`, `waistband`, `trouser_cuff`,
  `shirt_base`, `shirt_base_collar`.
- **Shirt**: `shirt_body`, `shirt_buttons`, `collar_spread`, `collar_button_down`,
  `collar_mandarin`, `sleeve_long`, `sleeve_short`, `cuff_barrel`, `cuff_french`, `shirt_pocket`
  (plus `trousers`, `waistband`, `trouser_cuff` so the figure is dressed).
- **Dress / gown**: `bodice`, `neckline_round`, `neckline_v`, `neckline_sweetheart`,
  `sleeve_none` (empty node), `sleeve_cap`, `sleeve_long`, `skirt_a_line`, `skirt_pencil`,
  `skirt_ballgown`.
- **Bodies**: a single node per body is enough (`mannequin`); it must carry the four body shape keys.

## Publishing a new version

1. Owner > 3D assets > Add a version. Upload the high and low GLB files. The server validates the
   container, lists the nodes and shape keys it found, and stores the files by checksum.
2. Record the source and licence (who made it, under what terms). Tick "professionally made" only
   for final models.
3. Move it through Validation, Processed, Preview and Approve, checking it in the studio preview.
4. Publish. The previous version is kept: saved designs and orders always reopen with the exact
   asset version they were made with.

Use only models you own or have a written licence to use commercially. Keep the licence document
with the atelier's records.

## Regenerating the stand-ins

```sh
cd frontend
npm run assets:build                 # writes public/3d/*.glb and public/3d/manifest.json
cd ../backend && go run ./cmd/api seed   # registers manifest entries (never replaces a published version)
cd ../frontend && node scripts/render-previews.mjs   # home page preview frames (needs the app running)
```
