# Implementation status

Last updated: 8 October 2026. Keep this file current whenever a feature lands or a blocker changes.

## Launch blockers

These must be resolved before the site takes real customers or real money.

| Blocker | Why it blocks | What is needed |
|---|---|---|
| **3D garment and body models are development stand-ins** | The studio works end to end, but the models are procedural shapes generated by `frontend/scripts/build-standin-assets.mjs`. They show options and proportions, not real drape, construction or fabric behaviour. Every stand-in is registered with `productionQuality: false`, the studio says so on screen, and the owner dashboard warns about it. The studio must not be called production ready until this is resolved. | Commission or license professionally authored GLB models (bodies with measurement shape keys, garments with the named parts listed in `docs/3d-assets.md`), upload them as new asset versions in Owner > 3D assets, review and publish. |
| **Sample photography** | Product, portfolio and page images seeded for development are licensed stock photos. They are labelled "Sample photo" on the site, with a footer note, so nothing is presented as the atelier's own work. | Photograph the real garments and work; replace images in Owner > Products, Portfolio and Pages. The footer note disappears automatically once no sample images remain. |
| **Payment provider credentials** | MTN MoMo (Collection API) and Orange Money (merchant payment Core API) adapters are implemented to the providers' published contracts but have not run against live or sandbox accounts, because no credentials were supplied. Methods stay hidden until credentials are set and the feature switches are on. | Merchant onboarding with both providers, sandbox testing using `docs/payment-integration.md`, then production keys in the environment. |
| **Legal review** | Privacy, terms, delivery and alterations policies are sensible defaults, not legal advice. | Have them reviewed for the countries you sell to; edit in Owner > Pages and policies. |
| **Production infrastructure** | Not yet deployed. | Follow `docs/deployment.md`: PostgreSQL with backups, S3-compatible storage, SMTP, HTTPS, secrets. |

## Done

### Customer site
- Home, shop with filters and quick view, product pages with size guide, wishlist and comparison,
  bag and guest or account checkout with idempotent order creation and server-side stock checks.
- Order tracking with a stage timeline, Mobile Money payment panel that polls the server (the
  browser redirect never marks an order paid), invoices, receipts and measurement sheets for print.
- Custom tailoring landing page and a nine-step request flow: garment, occasion, cut and fit,
  measurements (enter, saved profile or at the studio), fabric, reference photos with tags, notes
  and reordering, contact, review. Drafts survive a refresh; submission is idempotent.
- Quotes: view, accept, decline or ask for changes; accepting creates the order.
- 3D fitting studio: option switching from asset part names, fabric materials from CC0 textures,
  measurement-driven body shape, preset angles and turn buttons for keyboard users, lighter mode
  for weaker devices, a fallback when WebGL is unavailable, server-evaluated price and fit estimate,
  save and request a quote.
- Appointments: slot booking with availability rules, closures, notice periods and conflict
  protection in the database; customers can move or cancel within the notice window.
- Help and messages with photo attachments; private links for guests, history for account holders.
- Accounts: sign up, sign in, password reset, overview, orders and requests, versioned measurement
  profiles, saved designs, addresses, profile, password, signed-in devices, data download and
  account deletion.
- Policies, sitemap, robots, icons,
  structured data, Open Graph.

### Owner dashboard
- Overview of what needs attention, today's appointments and recent activity.
- Requests (review, verify measurements, change status with a message, internal notes, draft
  quote), quotes (line editor, deposit, validity, send, withdraw), orders (stages with the
  configured workflow, manual payments, recheck, refunds, production tasks, fittings, notes,
  schedule), payments, messages (replies, internal notes, assignment), appointments (week agenda,
  bookable hours, closures), customers.
- Products with variants, stock and photos; fabrics with colours, swatches and studio material
  settings; garment prices, option prices and defaults, fit rules and standard sizes; 3D asset
  versions with a review and publish pipeline.
- Portfolio with customer-permission checks; testimonials only with recorded consent.
- Editor for every content block and policy; business, tax, delivery, appointment and order
  workflow settings; feature switches that explain why they cannot be turned on; staff and roles;
  analytics with table views; read-only audit log.

### Platform
- Go API with sessions (hashed tokens, CSRF), argon2id passwords, lockout, role permissions,
  rate limits, security headers, structured logs, metrics, request IDs.
- Payments: provider interface, signed callback URLs, deduplicated provider events, every status
  re-verified with the provider, reconciliation job, one active payment per order, refunds recorded
  against verified payments, simulator refused in production.
- Uploads: type and size checks, re-encoding that strips metadata, private by default, retention
  purge, content-addressed 3D asset files.
- Notifications queue for in-app, email and SMS with deduplication; service emails explain how to
  change preferences.
- Tests: Go unit tests, Go integration tests against PostgreSQL, Vitest (including fit engine parity
  with the Go fixtures), Playwright end-to-end and responsive screenshots, copy checks.

## Not done yet

- **French translation.** The site is English only. For Cameroon this is the most important
  follow-up after launch blockers.
- SMS delivery uses the development log sender only; a real SMS provider adapter is not written.
- Photo-based body estimation is a switched-off placeholder with no provider integration.
- Dashboard gaps where the API exists but no screen does yet: creating appointments on a customer's
  behalf, product categories, new garment types and option groups, and per-garment measurement
  field lists. These are managed through seed data for now.
- OpenAPI description of the API.
- Lighthouse and load testing against a production-like deployment (budgets in
  `docs/performance-budgets.md`).
- The rate limiter is in memory; run a shared limiter at the edge when running several API instances.
